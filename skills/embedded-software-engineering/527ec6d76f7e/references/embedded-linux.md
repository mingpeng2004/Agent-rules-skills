# 嵌入式 Linux 专业路径

用于引导、内核/设备树、驱动、根文件系统、目标进程、交叉构建与升级。沿用项目已有 BSP/构建体系，不默认引入 Yocto、Buildroot、容器或新包。

## 构建与目标身份

确认 SoC/板卡修订、Bootloader、内核/补丁/config、DTB/overlay、工具链/sysroot、libc/ABI、rootfs 和应用版本组合。区分宿主工具和目标二进制；宿主运行成功不能证明目标 ABI 可用。

检查构建入口的下载、镜像写入、部署/重启钩子。锁定已存在依赖/源码来源和配置；新下载或安装按授权处理。可复现性至少记录完整输入和配置，不能只记录最终镜像名。

## 启动与硬件描述

沿启动链收集每阶段日志，定位最早失败点；检查加载地址/分区、console、bootargs、rootfs 识别、挂载和 init。不可凭应用未启动推断内核失败。

设备树核对 pinctrl、clock/reset、reg/interrupt、DMA、reserved-memory、电源/regulator、compatible 和驱动绑定；注意板卡修订和 overlay 顺序。更改 DTB 必须确认实际被引导器加载的产物，不能只改源码。

## 驱动与用户态边界

驱动适用检查：probe 错误回退、资源申请/释放、remove/unbind、IRQ/DMA 关闭顺序、并发访问、sleep/atomic context、缓冲所有权、用户输入边界、设备断开和电源管理。managed resource 不自动解决所有异步生命周期。

用户态通过明确设备接口与权限访问，不以提高全局权限掩盖接口缺陷。时序要求明确软/硬实时边界；不把普通 Linux 的平均延迟视作最坏保证。实时配置、优先级或锁页等措施需分析资源与系统影响，遵循项目要求。

## 进程与持久化

进程有启动依赖、健康/就绪、信号与关闭、重启上限、状态重建和日志限额。重启策略避免设备初始化循环、日志爆量、损坏配置或耗尽闪存。服务注册/自启是独立受控动作；可以设计配置，未授权不安装或启用。

持久数据明确 schema、原子更新、迁移、空间满、只读挂载、掉电/损坏的恢复。考虑闪存寿命、日志轮转和根文件系统保护。敏感信息不进镜像、源码或诊断日志。

## 升级与恢复

采用项目现有更新机制，按风险明确版本/硬件匹配、完整性/来源验证、分区/存储布局、掉电窗口、启动健康判据和回退。A/B、恢复分区等仅在工程已有或经设计批准时使用，不强行改造。

特别检查数据迁移与回滚版本的兼容性、引导元数据更新和不可逆熔丝/安全版本动作。没有支持回退的机制就明确不可回退及替代恢复，不把理论方案写成已验证能力。签名密钥和 secure boot 修改须单独授权与审计。

## 验证与证据

离线：交叉构建、ABI/ELF 与依赖检查、镜像/分区清单、config/DTB 审查、用户态逻辑/迁移测试。仿真只能证明所模拟设备和配置。

台架/实机适用：启动链、驱动 probe/断开、IO、压力和资源趋势、进程恢复、掉电/空间满/失败升级及回退。设备树、内核、rootfs、应用组合与日志绑定。写镜像、重启、挂载可写设备、远程 SSH 和电源故障注入都需核对动作授权和现场前置。
