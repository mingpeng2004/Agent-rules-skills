# 分诊流程：从「系统重启了」到可交付的复盘

> 本流程的每一步都规定了**产出什么证据**与**怎么判定它可信**，
> 避免用「看起来正常」代替「已验证」。

---

## 阶段 0：接反馈，先别问结论

用户说的是**现象**（「系统重启」），不是**机制**（「蓝屏 0x119」）。

**不要先问「是不是蓝屏了」**——用户看到的是黑屏重启。
直接去读机器，机器会告诉你真相。

> 按「反馈驱动主动调查」原则：反馈只是信号，
> 主动取证查根因，**先查再给方案**，不 surface-level 立刻动手。

---

## 阶段 1：钉时间与次数（易失证据优先）

```powershell
$os = Get-CimInstance Win32_OperatingSystem
'LastBoot : {0:yyyy-MM-dd HH:mm:ss}' -f $os.LastBootUpTime
'Uptime   : {0:N2} h' -f ((Get-Date) - $os.LastBootUpTime).TotalHours

foreach ($id in 41,6008,1001,161,1074) {
  '{0,-5} x{1}' -f $id, (Get-WinEvent -FilterHashtable @{LogName='System';Id=$id} -MaxEvents 2000 -EA SilentlyContinue).Count
}
```

**判据**：
- `41` 计数相对历史基线是否 +1 ⇒ 确认新增一次硬崩溃
- `1074` 在崩溃时刻**不存在** ⇒ 不是有计划的关机/更新重启
- `6008` 给出**精确崩溃时刻**（比 41 的开机时刻早 1–2 分钟）

> **易失证据要最先取。** 事件日志会滚动覆盖，dump 会被下一次清理抹掉。
> 拿完再慢慢分析。

---

## 阶段 2：读出停止代码 + 判定取证状态

按 [evidence-chain.md](evidence-chain.md) 执行，产出**两个独立结论**：

```
崩溃事实：BugcheckCode=281 (0x119 VIDEO_TDR_FAILURE)，蓝屏确实发生
证据状态：EVIDENCE_DESTROYED_DUMP_CREATE_FAILED（volmgr 161，BugCheckProgress 0x45）
```

**这两条必须分别记录，不得互相替代。**

---

## 阶段 3：崩前时间窗

```powershell
$start = (Get-Date).AddHours(-2); $end = (Get-Date)
Get-WinEvent -FilterHashtable @{LogName='System'; StartTime=$start; EndTime=$end} |
  Sort-Object TimeCreated
```

按 **Level 1/2/3**（用**数字**，不要用中文字面量——控制台 GBK 会把检索词本身糊掉）
过滤，再按 Provider 聚合找异常簇。

> ### 控制台编码坑
> 在中文 Windows 上，控制台会把中文输出成乱码，
> **连你在命令行里写的中文检索词也会被糊掉**，导致检索静默返回空结果。
>
> 纪律：
> - 匹配用**数字**（Level 1/2/3）或**ASCII**
> - 需要完整中文文本时，**写入 UTF-8 文件再读**，不要靠控制台
> - 脚本报红时先分清「被测物有问题」还是「尺子坏了」（见下）

---

## 阶段 4：候选排除（每条都要有实测数据）

对每个候选根因，找一个**能证伪它**的实测值。**实测排除了就写进「已排除」表**，
避免后来者重复怀疑同一条路。

| 候选 | 证伪手段 | 2026-10-15 实测结果 |
|---|---|---|
| 磁盘空间不足 | 查卷剩余 | 70.18 GB / 18.19% ⇒ ❌ 排除 |
| 内存超频 | `Speed` vs `ConfiguredClockSpeed` | 相等且为 JEDEC 标准频率 ⇒ ❌ 排除 |
| 有人长按电源 | 41 事件 `PowerButtonTimestamp` | `0` / `LongPowerButtonPressDetected=false` ⇒ ❌ 排除 |
| 计划重启/更新 | 崩溃前有无 1074 | 无 ⇒ ❌ 排除 |

**实测排除过一次，就写下来。** 台账的价值就在于省掉重复劳动。

---

## 阶段 5：写复盘（证据与推论分层）

复盘文档必须做到：

1. **结论表**：每个结论标注**证据强度**（实测确定 / 强推论 / 仅相关性）
2. **时间线**：全部实测，带时间戳
3. **全量历史表**：所有崩溃，不只是最近一次
4. **已排除项**：连同排除依据
5. **诚实边界**：明确列出**没查到什么**、**哪些结论未验证**

> **H5 证据先于结论 / H6 根因未定不得宣称修复。**
> 写「根因未定，但取证链已修复」是诚实的；
> 写「已修复」而根因仍是候选假设，是违规的。

---

## 阶段 6：把踩到的坑固化成护栏

复盘的最后一步**不是写完文档就结束**，而是让同类错误**不可能第二次发生**：

| 坑 | 固化方式 |
|---|---|
| 码表缺项 → 落 `UNKNOWN` | 码表补全 + **回归测试断言** |
| `0` 与「读不到」混淆 | 三态常量 + 测试覆盖两种输入 |
| 不查 volmgr 161 | 探测函数 + `evidence_status` 进台账与告警 |
| 待机信号只存不判 | 参与告警与趋势输出 + 测试断言 |
| 只追加 schema 撞 StrictMode | 安全取属性函数 + 老记录样本测试 |
| 诊断工具毁自己历史 | `-FullScan` 保留计数 + 测试断言 |
| 测试自身有 bug | 测试先自证前置量正确，再判断红绿 |

**验收判据**：每个坑都有**一条会在回归时报红的测试**。
没有测试的纪律等于没有纪律。

## 交付物清单

一次完整的崩溃调查应产出：

- [ ] 事件日志原始导出（UTF-8 文件，含完整 XML 字段）
- [ ] 崩溃全表（码 / 时刻 / 待机 / 证据状态）
- [ ] 已排除项表（含排除依据）
- [ ] 复盘文档（`incident_postmortems/YYYY-MM-DD-*.md`）
- [ ] 代码修复 + 回归测试（红→绿）
- [ ] 决策登记（DEC）
- [ ] 纪律同步（AGENTS.md / skill）
- [ ] **需要所有者拍板的待办**（提权动作、现场动作、硬件动作）

## 现场动作清单（AI 无法代办，必须转所有者）

以下动作**提权也解决不了**，必须明确告知所有者需要人工到场：

| 动作 | 为什么 AI 做不到 |
|---|---|
| `mdsched` 内存诊断 | 需**开机后有人按 Enter**，无人值守会跳过 |
| MemTest86 | 需**插 U 盘现场运行**多轮 |
| 逐插槽隔离内存 | 需拆机 |
| BIOS/电源/换件 | 需拆机，**停止自动执行** |

> **把「需要现场」说成「等我有权限就能做」，是把技术边界伪装成权限问题。**
> 两者都不该含糊。
