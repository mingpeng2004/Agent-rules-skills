# 根因调试、参数链与测量

在缺陷、控制精度、性能或现象来源不明时读取。

## 先证明现象属于什么

确认输入来自真实设备、仿真、测试夹具还是历史文件；检查运行 ID、原始路径、设备/版本/配置、时间、完整性、采样丢失和退出状态。最新文件名、截图、最近指针或错误码文本不能独立证明设备故障。

观察与解释分开：观察写实际输入/输出及来源；根因写待检假设和可反驳的预测。故障后先保存日志、崩溃现场、构建产物和配置，不先清理或覆盖现场。

## 最小复现与基线

在授权边界内建立最小复现，固定版本/配置/工况和通过判据。真实工件或设备缺失时只做离线复现/分析，记录不能证明的行为。基准路径若已有成功行为，比较确切调用链、初始化、tare/校准、单位转换和状态前置，不能凭“看起来一样”归因硬件。

给候选根因列：支持/反对证据、区分实验、预期结果、风险和成本。一次改变一个足以区分假设的因素；多个无验证修改叠加会失去归因能力。先排除版本/参数/数据来源问题，再决定是否需要控制调参或物理测量。

## 参数不生效

追踪：需求单位 → 配置/默认 → UI/profile → 编排/状态机 → 编码/量化 → 接收/边界校验 → 控制器状态/寄存器 → 生效/读回 → 实际行为。

检查所有覆盖点：启动、重新开始、重连、模式/方向切换、降级、故障恢复、设备默认和持久配置。记录最终值、来源、转换和时间；ACK 可能只表示接收，不能证明状态变化或实际控制输出。

如果传输正确而执行值被复写，修复所有权/生命周期；如果单位错误，修复统一转换边界；如果测试污染真实记录，修复写入隔离。不要用额外偏置或扩大死区掩盖链路错误。

## 控制与测量

先核对传感器来源、量程、标定、零点/tare、滤波、采样/输出频率、单位/缩放、延迟、量化和饱和。目标误差需考虑测量不确定性；不能在未确认测量能力时承诺更高精度。

分析要求与统计口径：完整区间、最大误差、超限持续/次数、收敛、振荡、丢样，以及适用模式/方向/阶段各自结果。平均值符合目标不代表所有样本合格。排除预热/稳态段必须有事先定义，不事后裁图达标。

DOE 前写目标、因素/范围、固定项、工况、顺序/重复、停止条件、证据和候选晋升门槛。离线重放/仿真筛选只产候选，不能证明实机稳定。涉及执行器的 DOE 单独核对现场与授权。

## 根因修复与退出条件

修复能解释现象的最小系统边界，避免多个入口各自补丁。新增回归覆盖触发条件、相邻状态/异常/边界；不能仅匹配实现代码。复测确认症状消失和约束仍满足，记录未覆盖场景。

遵循项目失败协议。没有协议时，第一次保留失败并修正局部假设；第二次同类失败更换假设/路径；第三次整理至少可区分的候选与下一方案，停止无依据循环。安全失败、证据冲突或范围变化立即暂停依赖动作，继续独立分析。

无法复现不是“已修复”；只修改配置、获得平均值或命令退出 0 不是根因验证。结论要说明验证层级、有效版本、工况和仍未知的部分。
