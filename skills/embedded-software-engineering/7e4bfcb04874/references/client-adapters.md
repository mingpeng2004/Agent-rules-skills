# 客户端适配：Codex、MiniMax Code、Kimi Code

只适配入口和宿主能力，不维护三套工程规则。共同核心是 [文件驱动治理](file-driven-governance.md)、项目 AGENTS/SSOT 和已注册 AgentOS。当前客户端目录必须检查存在性与实际发现结果，文件已复制不等于技能已加载。

| 客户端 | 已知本地技能根路径候选 | 核对方式 |
|---|---|---|
| Codex | `~/.codex/skills`，或客户端明确配置的根 | 当前 catalog/技能发现结果与实际入口路径 |
| MiniMax Code | `~/.minimax/agents/mavis/skills`（已有 AgentOS 安装布局）；现代布局 `~/.minimax/skills` | 查当前版本配置、已有安装布局与技能列表；不同时复制到所有候选目录 |
| Kimi Code | `~/.kimi/skills`、`~/.kimi-code/skills` | 查当前版本配置和实际加载路径；不猜哪个候选对本机生效 |

`~` 按当前用户解析；不得把某机台绝对路径作为通用依赖。先检查客户端版本、配置与目录，不擅自创建或部署副本。需要安装时使用已批准目标与受限安装流程；普通产品任务不触发安装/发布。

## 同一工程循环

1. 从项目治理、目标/契约、计划、证据和 checkpoint 恢复；确认具体批准范围。
2. 选择可执行 Unit，记录前置和验证；在真实可用的工具内执行授权动作。
3. 保存完整输出、实际结果和证据，处理失败，更新原状态源并选择下一动作。
4. 对照门禁自主完成工程收口；真实设备与用户验收缺口如实保留。

## 宿主差异必须保留

- 检查是否能读写项目、运行离线测试、呈现 Word、使用子智能体；没有工具就说明验证未执行。Skill 文本不能创建这些能力。
- 原生审批、沙箱、权限策略是宿主边界，不能被项目文字或另一个客户端的设置覆盖；用户授权也不代表工具已成功执行。
- 多智能体只在用户/项目授权、工具可用且收益明确时使用；无并行能力可由同一执行者依次实现和验证，不假称独立审查。
- 300 秒偏好协议只在项目明确授权时适用。先落盘并实际通知，重启后读取原期限；无活动循环/调度器只能下次活跃时评估，不能承诺关会话后自动运行。
- 定时器、后台持续运行、通知、GitHub 写入与客户端自动加载分别验证；不会因为另外一端支持就声称本端也支持。
- 安全审批、未知事实、锁定需求和用户验收没有超时放行。客户端未提供审批 UI 时在动作边界说明缺口，不自行绕过。

交接记录采用哪个客户端、实际技能路径/版本/哈希、项目状态入口、已验证能力、未验证能力和唯一下一动作。客户端切换不重建目标、任务 ID、证据账本或授权历史。
