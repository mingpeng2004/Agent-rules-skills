# 维护本 Skill 与受限发布

仅当任务明确是维护、验证、发布或安装本自建 Skill 时读取。普通产品缺陷修复、固件开发、trace 分析及业务文档生成，不触发 GitHub 同步、Skill 安装或客户端配置更改。

## 来源与范围

- 注册自建来源：`https://github.com/mingpeng2004/Ming-Skills`。
- 维护源以项目注册表声明的 authored Skill 路径为准，不能把所有个人技能、第三方技能或宿主缓存当发布源。
- 发布仅包含白名单内的 Skill 文本、经过同源/安全/视觉验证的 DOCX 模板，以及明确登记的必要共享工具/说明。
- 排除产品源码、现场 trace、内部报告、`.agentos` 私有状态、凭据、令牌、主机敏感信息和无关工作区文件。引用产品资料时使用去标识的示例，不能复制真实内容。

## 验证 → 独立审查 → prepare → sync

维护工具入口为维护项目的 `tools/ming_skills.py`。该工具属于发布工程，不打包进本 Skill 的执行路径；先查看当前实现/接口与无副作用帮助，使用实际支持的参数，不照抄猜测选项。

| 能力 | 目的与边界 |
|---|---|
| `validate` | 离线验证注册源、路径/格式白名单、内部链接、DOCX 源哈希与安全边界 |
| `prepare` | 接受与当前内容摘要一致的已通过审查报告，实际重跑离线测试并绑定内容及工具指纹；不发布远端 |
| 审查/ready 记录 | 依据完整验证与审查结论，绑定具体内容哈希/清单；不能仅凭文件存在或状态字符串放行 |
| `sync` | 仅在用户授权的仓库/范围内同步已验证、审查并绑定哈希的内容；内容变化使旧批准失效 |
| `install` | 安装已核验版本到明确的客户端目标，保留本地修改并报告发现状态 |
| `status` | 只读检查本地准备状态与上次已核验远端记录；不联网，也不证明远端当前未变化；状态检查本身不赋权 |

版本升级后重做相关结构、安全、同源和行为验证；检查文档未把项目个例升级成通用限制。发布前核验实际白名单 diff，不将普通产品更新当 Skill 更新。只提交/推送正常历史；禁止 force push、覆盖未知远端或绕过冲突。远端变化先调查再合并/重做准备，二次相同内容同步应无额外提交。

自动同步只能处理当前有效的 ready/内容哈希，不得自动审查自己的未知改动或把失败检查标为通过。失败保留完整结果；网络结果不明先核查远端状态再重试。反馈、撤回或变更使相应待发布内容失效；既有网络/仓库授权不扩展至其他目标。

安装、远端发布、定时自动化和软件开发是不同动作，分别核对已有授权；无授权时先完成离线可审阅结果，再停在相应动作边界。交付报告列实际版本/哈希、检查证据、真正发布/安装范围、客户端发现结果及未执行项；不把计划、已复制文件或成功退出码当成用户/设备验收。
