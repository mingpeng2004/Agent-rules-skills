# 每周治理与技能学习

从当前源文件和实际证据开始。读取项目规则、AgentOS BOOT、已有任务与本工作流。
既有 owner 授权覆盖每周受控发布，无需重复索取；未知权限、凭据、公开隐私风险与
真实硬件动作不因计划授权或超时自动放行。

1. 调用受控工作区 tools/weekly_learning.py scan，识别配置范围内的新项目、技能与
   变化的规则/DEC/教训/复盘。记录真实零结果、无法读取、未扫描和扫描上限的区别。
2. 阅读变更记录和相关源码/原证据，分开事实、证据状态和归因假设。否定性结论注明
   获取方式、时点和复核窗口；仅文件名、空日志或工具 exit 0 都不足以证明成功。
3. 将可证实且可复用的教训映射到对应自建 Skill 或治理清单。每条保留私有来源摘要、
   适用边界、反例和真实验证结果。项目特例不强升通用规则。重复/无价值项不制造改动。
4. stage 收集治理与所有发现技能；保留不同变体、许可证和索引状态。供应商内部或
   无再分发依据的第三方只登记索引。原始项目状态、trace、机密和本机路径不公开。
5. 对新规则造已知失败案例验证会响，再验证正常/边界。检查实际覆盖文件数量、输出
   完整性与源摘要。记录真实独立审阅和 tests；旧 package/review 一变就重新验证。
6. prepare 后 publish 到 owner 明确指定仓库，保留无关远端内容；发生并发更改先调查。
   远端树/内容回读一致才报告成功，未变化不创建空提交；未知写入先读回核实。
7. 保存私有审阅/检查点与发布回执，公开只放可移植资产和脱敏举证。安静跳过未变化
   状态，发生有意义改进、成功发布、失败或需人类决定时汇报。

输入：有范围的扫描源、既有授权、变化记录、当前技能/治理和实际验收证据。
输出：可复用的方法增量、完整技能目录、来源/许可证、测试摘要、已验证远端提交。
验收：扫描覆盖可解释、未检项如实列出、无机密外发、测试和审阅绑定当前源、读回一致。
失败处理：证据不足保留提案；泄漏/授权失败阻发布；并发远端变更保留现场，不强推。
每周任务是调度要求，不是永久在线保证；首次定时触发前不能声称已实测无人值守。
