# 分层验证、证据与发布

用于测试/构建/联调/设备验证和发布。按项目已有标准与实际风险选择，不为“流程完整”启动无关测试。

## 验证契约

执行前确定目标需求、输入/工况、期望行为/阈值来源、版本/配置、最低证据层级、证据保存和停止条件。检查测试/构建脚本是否写真实记录、连设备、下载或执行后处理。

| 层级 | 可支持的结论 | 不能替代 |
|---|---|---|
| 静态 | 契约、代码路径、配置/链接布局的审查 | 实际时序、物理状态 |
| 单元/构建 | 已执行逻辑用例、相应配置可编译链接 | 协议实机、生产验收 |
| 集成/仿真/台架 | 被测组合和模拟/台架工况的行为 | 未覆盖目标/环境/物理动作 |
| 实机 | 指定设备、版本、配置和工况的真实行为 | 其他设备或未经测试的完整生产工况 |
| 用户/生产验收 | 明确验收范围与对应接受证据 | 未获实际验收的部分 |

AgentOS 的 E0–E4 定义以其当前协议为准。尤其其 HIL 可记录为 E3，不能自动升级为所有真实设备声明；物理结论按框架要求补 E4。独立模式也保留上表边界。

## 用例选择

需求对应正常、异常和边界；重要状态覆盖启动/取消/超时/断链/复位/恢复。协议覆盖畸形长度、CRC/校验、序号/重复/迟到、端序/缩放和旧新兼容；并发覆盖压力/资源耗尽/关闭/重入。

编译验证说明目标/配置/优化/告警、是否干净构建、产物与符号/map。遵守项目告警和覆盖率门槛；新增告警不得忽略，旧问题明确归属而非声称零警告。覆盖率口径包括范围与排除理由，不能用高覆盖率证明遗漏的关键工况。

性能/精度/长跑先有基线和判定方法，再给完整数据。报告负载、环境、持续时间、采样、缺失/丢失、最大值/分位数或适用统计及各模式/方向/阶段。预设全程约束不能改成均值判定。测量开销和不确定性注明。

## 证据保存

每次实际运行保存完整 stdout/stderr、退出码/结果、开始/结束时间、命令/动作、工作目录、适用环境、输入/配置/产物哈希和日志路径。保护凭据，必要脱敏但保留可核查的非敏感信息。截断/超时/断连需保留原输出并标失败/未知。

合成/模拟/fixture 明确标注、隔离写入；允许它证明测试逻辑，不能满足实机/安全/生产门禁。更正证据追加事件，不能改历史产物以配合结论。动态数据与验证结果随版本/工况变化失效。

读取测试详细结果，不仅看退出码。跳过、预期失败、无用例、前置不满足须单列，必需用例未跑不能交付为全绿。失败后只重复与修复/疑点有关的检查。

## 受控设备验证

核对目标身份、实际连接/电源/负载/工件、急停与项目安全状态、当前版本、目标产物/写入区域、明确动作授权及恢复入口。缺事实时停在边界，不凭历史端口或自动扫描选择目标。

烧录/镜像写入分开报告预检、擦写范围、写入、校验、复位/启动、运行版本及真实功能。不得把工具成功、PING 或版本字符串当作控制闭环/生产完成。初始化可能运动，现场不满足不执行。

## 发布绑定与兼容

发布清单绑定源码 revision；无 Git 时绑定可复现源码快照/清单。再绑定编译器/SDK/sysroot、依赖锁/许可证、构建参数、板卡/目标、协议/配置 schema、产物/hash 与运行有效版本。

有效版本从实际导入/启动/目标读回取得，文本搜索只是静态检查。Host/FW 分别构建/验证，明示允许的组合、升级顺序和不兼容响应。构建后 EXE/镜像、安装目录与真正启动路径都要核对，防止旧副本。

执行发布/签名/上传/部署前核对该外部动作授权。新依赖/工具审计来源、版本、漏洞和许可证；未查不能宣称无漏洞。遵守项目安全扫描；扫描只证明其规则覆盖范围。

## 回退和交接

定义回退触发、前版本/配置/数据快照、目标身份、操作入口、迁移可逆性和验证。对不可逆布局/熔丝/安全版本明确阻塞或替代恢复，不能承诺不存在的回滚。回退本身也可能受控，不自动执行。

发布报告逐项列 verified、failed、blocked、needs-user-acceptance，说明 N/A 理由、已知限制、未决风险及下一动作。工程产物满足既定门禁可交付，实机/用户验收待办单列；整体包含物理验收的任务不能提前关闭。
