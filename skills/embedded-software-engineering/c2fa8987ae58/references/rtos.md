# RTOS 固件专业路径

适用于任务调度、同步、消息/缓冲、栈堆、RTOS 中断接口与长期运行。先确认内核/版本/端口、配置、时钟和调度模式，不默认 FreeRTOS 语义适用其他内核。

## 任务与时序模型

建立适用任务表：职责、触发方式、周期/截止时间、优先级、执行时间证据、最长阻塞、栈、共享资源和故障响应。CPU 平均占用低不能证明截止时间满足。

核对抢占、时间片、tick/无 tick、延迟 API 语义、时钟精度/回绕及 ISR 唤醒。周期任务应明确相对延迟和绝对周期的差别，覆盖执行超期的处理。将高优先级任务、ISR、临界区和共享锁的干扰计入分析；需要时使用适用调度分析，并说明假设和测量局限。

## 同步与所有权

把共享资源、读写上下文、锁顺序/最长持有时间、生命周期及取消/超时后的拥有者画清楚。

- Mutex、binary/counting semaphore、event、queue 和 notification 语义不同，不能只因 API 名称相似替换。
- 核对 mutex 的优先级继承/上限机制及嵌套限制。信号量或忙等不自动提供优先级继承。
- 固定锁顺序，避免持锁等待未知回调、I/O、另一个任务或递归进入。超时返回并不自动释放调用方全部资源。
- 任务删停、取消、重连、复位时，消息/缓冲/句柄的所有权仍要有明确归宿。
- 队列规定容量、生产/消费峰值、背压/丢弃、过期消息、重复处理和满队列行为。发送指针时保证缓冲生命周期及消费者完成后的释放。

## 中断与 RTOS API

检查端口对 ISR 优先级、嵌套、临界区和允许内核 API 的要求。优先级编码与内核边界从目标配置确认。区分线程态和 ISR 专用调用、阻塞参数及唤醒后调度规则。不要为了消除 assert 任意降低优先级或关闭检查。

不允许在禁止内核调用的高优先级 ISR 中调用队列/锁等 API；需要事件转交时设计明确桥接路径。ISR 内重试到成功可能把队列压力变成实时故障。

## 内存与故障

确认静态/动态分配策略、分配器、碎片与失败处理、任务栈单位、栈对齐、FPU/中断上下文和水位测量局限。不能把最小一次测试的高水位当最大上界。

长期任务优先有界资源；重复创建任务/队列/定时器检查释放。ISR 不进入不适用的分配器。溢出/分配失败钩子和 watchdog 对应可诊断行为；所有任务共享喂狗可能掩盖单任务失活，应定义进展/活性判据。

复位/失联恢复不能由多个任务争抢设备初始化。关键控制和通信/UI 的故障隔离要明确；软件定时器回调所处任务及阻塞限制按内核核对。

## 验证

离线测试状态机、消息所有权、锁顺序和超时；静态核对 RTOS 配置与调用上下文。集成增加突发/满队列、慢消费者、优先级干扰、资源耗尽、取消及重连。记录事件时间线、最长阻塞、超期、栈/堆趋势、丢弃和恢复次数。

真实调度/中断时序与长期稳定必须在匹配内核配置、优化级别和目标工况下验证。trace 工具和日志有观测开销，记录配置。没有执行压力/长跑时，仅报告分析和计划。
