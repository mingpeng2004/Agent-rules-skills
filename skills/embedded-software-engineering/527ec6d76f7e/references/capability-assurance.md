# 客户端能力保障与对照验证

AgentOS能提高弱模型的工程约束、可恢复性和交付稳定性，不能把模型上限等同另一模型。目标是同类任务达到相同可测验收条件；未经同题实测不能宣称MiniMax、Kimi或Codex等效或提高了某百分比。

## 强化机制

- 任务契约绑定目标/框架/计划/验收/状态五类实际文件及摘要、必需需求/门禁、证据最低等级和授权边界。
- 可用时使用共享发布工程的 `tools/engineering_gate.py` 独立检查文件/证据/摘要/新鲜度。缺工具则报告未执行，不伪称机器门禁通过。该工具只读验证，不执行动作或产生授权。
- 关键不变量落实到代码/协议测试；高风险修复按任务计划增加有意义的变异验证，例如注入单位错误、恢复旧阻塞路径、撤掉释放，确认测试实际失败。不能只测与实现同形的断言。
- 实现和验证分离：验证方拿原始产物/输入和需求，不只拿实现者结论。失败保留反例与被否假设，按原协议换路/升级；能力不足交更适用的执行器或用户，不扩大权限、不反复盲试。
- 工程自验、集成、设备和用户验收分层；文档门禁只证明文件/证据契约，不证明物理行为。

## 同题基准

选真实代表性任务及经批准的隔离夹具：协议/单位与边界、并发/状态机、参数生效、发布/恢复、历史治理。保持输入、工具权限、任务难度和验收相同，记录客户端/模型/版本、目标与提示修订、实际结果、失败/重试、耗时和实际Token/缓存用量。

先验收任务质量，再比较资源；缺模型版本、真实运行、原始输出或遥测保持unknown/not-run。一次成功不能外推所有嵌入式开发能力。持续维护最小反例回归库，按实际缺陷窄化规则，不堆积重复宪法、无关参考或巨量必读上下文。

文件协议和同权限脚本不是不可绕过的宿主安全网关；不能认证用户身份或阻止有相同权限的代理伪造文件。强制权限/安全仍依宿主控制。任何模型与工具升级先做匹配基准后才宣传提升。
