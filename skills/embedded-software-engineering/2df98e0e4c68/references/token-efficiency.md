# Token与工程资源预算

最少化原则：在把事情做好的前提下，采用满足目标、质量、证据与安全约束的最小文档、上下文、动作、验证和协作；既不过度工程，也不以省略必需工作达成表面低消耗。门禁满足即收口，复用优先于重复。

在长程任务、上下文膨胀、跨代理重复探索或用户要求降低消耗时读取。目标是在相同质量门禁下减少无关输入、重复推断和重复执行；不得省略必需证据、缩窄用户验收、猜测未知或掩盖失败。

## 输入按需加载

入口只放目标、约束、当前Unit、权威路径和下一动作。专业参考按任务路由读取，先查目录/符号/契约，再读相关片段；修改前读取足够上下文，不能以片段代替完整影响审查。已经读取且内容摘要未变的静态文件可引用既有结论；动态任务/设备状态按新鲜度刷新。

完整日志、trace、源码快照和推导产物保存在文件，活动上下文携带退出码、适用范围、异常摘要、证据路径/哈希。正常结果简短汇总，异常和冲突定向展开原始输出；不能因输出截断就判通过，摘要不能替代关键门禁的实际执行与完整留档。

## 复用而不失真

缓存键至少绑定源码/配置/工具链/输入和适用工况；命中仅复用其可支持结论。修改影响依赖时使对应缓存失效；清单哈希一致不能证明真实设备状态仍相同。相同证据用ID引用，不反复复制到计划、状态和报告正文。

测试先针对影响面定位，再完成项目要求的集成/全量门禁。通过后无新修改/失败/疑点就不重复全量；门禁必需的全量测试不能因省Token而跳过。重复转换、摘要、清单、校验用已审查确定性工具，结果仍留完整证据。

## 计划、沟通和分工

在已授权方案内推进Unit，不重新生成全项目规划或反复申请同一权限。计划只更新新事实、影响与剩余依赖；检查点保留当前结论、未知、被否假设及唯一下一动作，旧过程归档。复杂度或风险上升时可以扩大调查，不人为维持过小上下文导致错误。

仅当并行收益高于启动/交接成本时委派；子任务给目标、边界、最小原始材料、验收与输出路径，不默认复制全部历史。按模块/文件分工避免重复读取/实施，独立审查聚焦高风险结果；实现者自述不能替代独立证据。模型/思考强度遵守宿主与用户选择，不未经允许静默换模型来承诺节省。

## 预算与评估

在现有PLAN记录适用的Token/工具调用/时间预算、观测来源和质量门禁，不强制每小任务单独建预算文件。使用客户端实际提供的输入/输出/缓存用量；没有遥测就标unknown，字符数估算必须注明derived且不能冒充实际Token。

比较优化前后须用相同任务、模型/工具、数据和验收，报告实际消耗、完成质量、重试/失败及耗时。发现质量下降、证据缺失或异常重复立即重规划，不把更少输出字数等同更低总成本。不得宣称未经测量的节省百分比。
