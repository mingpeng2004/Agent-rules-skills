# 记录生命周期与治理收口

用于阶段收口、接管发现新旧记录冲突、历史清理或治理膨胀。目标是让当前决策只消费当前有效信息，同时保留历史；本规则不授权删除数据或重写证据账本。

## 当前视图与历史证据

日常上下文只加载现行目标/锁定约束、契约、活动计划/任务、最新checkpoint、未决授权/风险和适用证据索引。完整过程、旧快照、原始日志按ID定向检索，不逐轮全文重复注入。已完成任务只在活动视图保留结果、适用版本、后继任务及证据入口。

每种事实只有一个写入源。当前状态是可更新投影，证据账本和决策历史按项目规定只追加；纠正时更新当前投影并追加失效/替代事件、原因及后继ID。不能在活动摘要中不断追加相反历史叙述而没有适用范围。精简重复叙述，不删约束或隐藏风险来缩短记录。

## 生命周期与新鲜度

沿用 active、superseded、stale、archived 或项目等价标签；标注ID、责任、来源、适用目标/版本/配置/工况、时点及后继/失效原因。active不等于verified。源码/配置/目标/设备/工况变化即检查证据适用性；硬件状态可能一次操作后即失效。未改变的设计理由可长期有效，不能统一用天数或最新文件时间判权威。

MD改动使Word快照stale；归档保留当时版本/摘要，旧批准不能用于新内容。用户原始需求SSOT不得因年代久远自动退役。

## 贯彻到门禁

| 恢复点 | 必做检查 |
|---|---|
| 开工/新会话 | 权威映射、现行基线、最新反馈/checkpoint和未知 |
| 每Unit结果 | 追加证据、刷新唯一状态投影、标记受影响旧证据 |
| 变更评审 | 需求/契约/资源/风险/依赖/验证/配置/回退影响矩阵 |
| 阶段/发布收口 | 活动索引、后继关系、文档同步、悬空引用、待验收及技术债 |
| 清理请求或重复冲突 | 分类、引用审计、归档方案和授权，再实施 |

风险/假设/依赖有拥有者、触发条件、验证或缓解及退出条件。未知项不能重新包装成已接受风险。发布绑定源码/工具链/配置/产物/运行版本，兼容与回退另验；这些职责写入现有FRAMEWORK/PLAN/ACCEPTANCE，不强制新建空文件。

## 分类归档与清理

1. 盘点候选路径、类别、大小/作用、适用版本、全部引用和保留要求；只读阶段不删除。
2. 区分缓存/可重建产物、被替代说明/快照、真实日志/验收证据、契约/锁定需求/凭据/用户资产，不从名字猜类别。
3. 说明当前替代、归档清单/路径、引用更新、恢复和具体授权。可回滚归档按已有授权；删除、未知风险和受保护资产须明确确认。
4. 沿用archive布局，保留原始字节/SHA256和来源映射；更新活动索引及稳定ID/后继说明，不移动仍为权威的原始SSOT。
5. 验证归档前后摘要一致、引用和恢复入口可用、当前视图无冲突/失效条目；代码或构建输入清理还需相应回归，不能只验证文件变少。

原始证据只追加更正，不改历史结果。大范围移动、递归删除和自动保留期清理不是默认动作。没有授权就交候选清单，不把“希望包含清理机制”解释为批量删除授权。完成报告说明当前视图精简、归档与摘要/链接检查、待验收和风险；不能承诺永久无噪声，靠门禁持续治理。

授权可以绑定具体清理索引：逐项列绝对路径、分类、动作（保留/归档/删除）、来源/内容SHA256、引用审计、保留要求、恢复位置和批准范围。执行前确认路径未越界、摘要/引用与批准时一致；变更项暂停重评，不扩大到相邻文件。只有明确批准删除的项才删除，其他项按归档或保留处理。索引及执行/恢复验证结果保留为审计证据。
