# 生产级技能路由

先读取项目 AGENTS、目标、当前任务和 AgentOS BOOT。已有契约、权限、证据账本保持
权威。路由文件只引用它们，不建立第二本任务台账。此 Skill 可独立提供操作方法；
机器检查需要已安装 AgentOS 的 bin/agentos_skills.py（Python 标准库）。没有工具时
按本流程手动核对并注明限制，不能声称门禁已运行。

1. 明确当前 Unit 的交付物、目标、范围、输入文件、验收和风险。将每个验收项关联到
   需求/约束 ID；未定值保持 unknown。风险由任务契约确定，不能为通过门禁降级。
2. 查询 policies/SKILL-REGISTRY.json 的能力项。只选一个直接负责交付物的主能力，
   按需增加至多两个约束能力。只加载入口和对应引用文件；不要加载整套技能矩阵。
3. 输入缺失先补上游产物；候选方法、缺失 provider、命中歧义均保持 blocked。
   项目自定义实现可优先于客户端或内置实现，但不能覆盖用户目标、安全、锁定 SSOT。
4. 执行一个已有授权的 Unit，立即获取真实输出并验收。route 成功只表示具备执行
   前置；gate 要核对任务输入、规则、产物摘要、最新证据、适用范围与独立复核记录。
5. 将 route/gate 的引用写回现有任务与检查点。失败两次换路，三次列根因表，四次
   升级并继续无依赖的工作；不要通过增加角色、技能或重复同一路径掩盖阻塞。
6. 复盘教训生成 proposed_for_review 条目，关联原始证据与拟修改的清单。72 小时是
   复核目标；需实际审阅、验证与授权后才进入共享技能，不自动发布规则。

输入契约：当前 task、goals、constraints 三个项目内真实文件，声明输出路径和风险。
输出契约：主能力对应的项目产物、现有 claims.jsonl 证据、独立检查记录、路由与门禁报告。
验收：输入有效、来源未变化、输出满足任务 DoD、门禁要求的等级/适用范围/时效匹配。
上游：项目目标/框架契约与已完成依赖。下游：集成、发布或真实设备/用户验收。

常见失败及处理：

- 注册了名字却没有可运行方法：保持 candidate，不计作已部署技能。
- 脚本 exit 0 但无记录或验证空集：要求非空输入、输出和检查；先注入已知坏案例。
- 引用旧产物或把模拟当实测：重算摘要、检查最新事件及时间，按适用范围拒绝替代。
- 把技能优先级当权限：回到既有授权与安全前置，超时不能放行安全或事实缺口。

任务方法、FMEA/V模型/阶段评审/ECN、命令及复核格式见
[references/workflow.md](references/workflow.md)。技能入库前用

在真实适用任务验证后再更改能力状态。模板不证明标准认证、量产能力或模型能力对齐。
