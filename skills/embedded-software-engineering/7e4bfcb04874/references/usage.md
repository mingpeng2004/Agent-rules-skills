# 使用示例

以下是请求范例，路径/设备/数值应由实际项目发现或用户提供；不是授权、事实或执行结果。

## 接管与规划

“使用 $embedded-software-engineering 只读接管这个工程，核对治理、构建入口、协议与当前任务。给出风险和开发方案，暂不执行代码修改、测试或硬件动作。”

预期：读取证据，说明未知；选择相关平台资料，形成可验证方案；保持只读边界。

## 已批准开发

“使用 $embedded-software-engineering 按已批准方案修复通信解析缺陷，完成离线回归和构建。不要连接设备或新增依赖。”

预期：识别批准范围及现有改动，复现/修复/验证，追踪协议兼容；先查测试/构建副作用，实机验收单列。

## RTOS 问题

“使用 $embedded-software-engineering 分析高负载下控制任务偶发超期，先离线检查任务优先级、ISR、锁和队列，给出区分根因的验证方案。”

预期：以时序/所有权证据分析，不凭平均 CPU 或单个 trace 断言根因，不擅自改优先级或操作设备。

## Linux 升级

“使用 $embedded-software-engineering 审查升级设计，检查版本组合、掉电恢复、数据迁移和回退。只读，不登录目标或写镜像。”

预期：确认实际机制，报告可逆性与验证缺口；不假定 A/B、签名或恢复分区已经实现。

## 发布检查

“使用 $embedded-software-engineering 检查发布候选的软件/固件版本、构建产物和验收记录，分别说明工程交付及实机验收状态。”

预期：核对运行有效版本和产物来源；必需测试缺失不算通过，未有设备证据不宣称生产通过。
