# 生命周期、需求与架构

用于新功能、非平凡变更、设计和维护；小改动只取适用项。

执行骨架遵循 [文件驱动治理](file-driven-governance.md)：先映射目标与框架/契约 SSOT，再用 Phase/Task/Unit 计划推进到验收证据与既有 checkpoint。本文补充工程设计内容，不定义另一套任务状态。

## 需求成为可执行验收

每个适用需求记录来源、行为、输入/输出、单位/有效范围、工况、通过条件、验证层级和负责人。性能数值无来源时记录待决定项及如何测量，不能把示例值变成要求。

区分产品功能、质量属性、环境约束和安全约束。描述正常、边界、错误、启动/关闭、失联/重连、复位、掉电、升级等适用状态。危害分析指出触发条件、可能后果、检测及缓解；安全机制本身也要验证故障路径。涉及专门行业标准时确认适用版本和项目要求，不凭本 Skill 宣称认证。

把需求映射为 `REQ -> 设计/接口 -> 实现 -> 验证用例 -> 证据 -> 交付状态`。沿用项目已有 ID，不为同一需求建立另一套编号。

## 架构决策

识别实时控制、设备访问、通信、状态管理、持久化、UI 等边界。模块明确资源所有权、生命周期、接口、线程/中断上下文、失败语义。共享状态尽量通过明确消息或受控接口修改；集中管理设备句柄、控制权和配置生效。

关键决策比较可行方案、适用约束、代价、兼容和回退；跨协议/调度/安全边界变更走项目决策记录。小的命名与局部实现不制造大量 ADR。

## 时序与资源预算

按任务选择需要的预算，并说明数据来源及测法：

| 预算 | 设计时检查 | 验证 |
|---|---|---|
| 时序 | 周期/截止时间、阻塞、执行上界、中断负载、通信等待 | 适用最坏工况、最大延迟/抖动/超期计数；不是仅平均值 |
| 内存 | Flash/RAM 区域、栈堆、缓冲上限、分配失败、生命周期 | map/section、栈高水位/余量、压力与长期趋势；测量不当作上界证明 |
| 带宽 | 峰值生产速率、帧开销、队列容量、背压/丢弃规则 | 突发、慢消费者、断链后恢复、溢出计数 |
| 存储 | 写入频次、擦写寿命、原子性、日志容量 | 掉电/损坏/空间满及恢复；记录适用磨损模型 |
| 功耗/热 | 状态、唤醒、峰值负载、外设耗电 | 指定硬件与测量设备的实测，离线只能分析 |

余量来自目标和风险，不臆造统一百分比。无依据时提出测量/确认任务。长时稳定需说明持续时间、负载、环境、重启/故障次数和观察窗口。

## 接口与状态机

接口区分请求被接收、处理开始、完成、生效、失败。协议考虑长度/类型验证、端序、单位/缩放、序号、完整性、超时、重复和版本兼容。重试写入/运动/迁移前检查幂等，不能把 ACK 等同业务完成。

状态机定义每状态允许命令、进入/退出条件、超时、取消、错误及恢复。安全联锁是显式约束，不能通过“异常忽略后继续”绕过；安全状态由项目/硬件定义，不假定关闭某输出对所有设备都安全。

配置链路追踪来源与优先级、默认/持久值、运行覆盖、传输编码、设备边界校验、实际生效值/读回、复位/重连。明确哪些状态重载参数；避免隐式复位和双重默认覆盖。

## 实现与验证选择

实现前读现有抽象和调用链，避免只改一个表面入口而保留另一个旧路径。缺陷优先复现和红测试；硬件专属问题无法离线复现时记录局限，不能伪造红绿结果。回归覆盖系统性根因、正常/错误/边界，不只断言代码写法。

用逻辑测试检查规则、协议解析、状态迁移；用平台集成检查接口；用设备证据检查真实时序、精度和故障行为。测试设计与影响面相称；纯文案或无行为改变不强制写实现镜像测试。

## 发布后维护

日志关联版本、启动/运行 ID、状态和错误，避免高频控制环同步写盘/输出。限制日志量、队列和重试；诊断失败不应无限占用关键路径。恢复有最大尝试、退避、失败状态和可人工介入入口。

技术债与衍生问题登记为后续任务。经验只有在证据支持且适用范围清楚时晋升规则；禁止把一次特殊板卡/项目故障推广成所有平台的绝对要求。
