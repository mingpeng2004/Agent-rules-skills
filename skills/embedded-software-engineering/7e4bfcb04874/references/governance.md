# 治理适配、任务状态与恢复

在进入项目、跨会话恢复、状态冲突或权限不清时读取。

非平凡任务同时按 [文件驱动治理](file-driven-governance.md) 映射目标、框架/契约、计划、验收和状态；客户端入口/能力按 [客户端适配](client-adapters.md) 核对。映射原有路径，不创建平行治理系统。

## 接管顺序

1. 核对用户指定根目录与当前工作目录；多工程时区分源码、构建输出、部署副本。读适用 AGENTS，发现其 SSOT，不凭习惯猜路径。
2. 读需求/不可变约束、设计目标、决策登记、最新任务/checkpoint。状态面板可能落后；与最新记录、源码及实际产物交叉检查。冲突不静默择一。
3. 检查 Git/其他版本状态。无版本库时如实说明，以源码清单/快照/哈希绑定本次变更；不伪造提交、分支或 PR。保留用户改动和历史证据。
4. 检查清单、工具链版本约束、构建入口和钩子、测试配置、产物路径。先静态看脚本再执行；源码能回答的问题不问用户。
5. 输出简短基线：目标、平台、模块、接口、现有验证、当前风险/未知、授权动作及下一步。读取配置不能证明运行设备状态。

## 选择治理适配

| 检测到的现状 | 行为 |
|---|---|
| 注册的 AgentOS 项目 | 用配置中声明的目录/协议/工具，复用账本与状态 |
| 其他治理 | 把本 Skill 的目标、单位、证据、检查点映射到既有记录 |
| 无治理 | 方案批准后为当前任务建立最小记录，默认 `docs/engineering/<task-id>/`；遵守项目路径习惯，不生成空章程 |
| 必需文件缺失或相互冲突 | 标 unknown/conflicted；仅阻塞依赖它的动作，继续可独立调查 |

项目自己的控制不变量（特定轴、单位、限制、时序）在项目 SSOT 中维护。通用 Skill 不复制成全局要求。既有严格门禁保留，不能用轻量分类规避。

## AgentOS 适配

从环境 `AGENTOS_HOME` 或项目明确登记的位置定位 AgentOS，不把个人绝对路径写成通用依赖。读项目 `.agentos/project.json`，以其字段定位 status、tasks、checkpoint、evidence ledger 和 working memory。当前配置缺字段时读框架导入契约，不猜补 schema。

按框架要求加载 BOOT、AGENT-IMPORT、宪法、任务/证据/质量/恢复和委托协议。未注册项目不由 Skill 擅自注册或安装框架。框架必需路径不可读时说明缺口，不宣称治理验证成功。

操作已有命令前读参数与实现或无副作用帮助，使用当前版本的原生工具记录/验证；不手写伪造验证事件。保持 append-only 证据历史，更正用新增失效/修正事件。动态快照可更新，证据产物和决策历史不覆写。

复杂方案须先确认，已有有效批准直接引用；已批准任务内普通实施直接推进直至工程门禁满足或明确阻塞，不逐工具重新审批。项目已有明确的普通偏好委托规则可用于后续取舍，须遵守实际通知、落盘、范围、回滚和反馈优先；不能替代复杂方案确认、硬件授权、缺失事实或真实验收。无委托时不引入五分钟默认。等待时推进独立任务，不承诺会话关闭后自动继续。

## 最小外置状态

优先写现有任务，不再建一份重复的“Skill 状态”。至少包含：目标/范围/DoD、当前 Phase/Task/Unit、依赖、通过条件、证据要求、授权边界、未知/冲突、实际结果、下一动作。

每 Unit 开始前记录意图、前置、动作类别、预期结果和恢复；结束后记录观察到的结果和证据。轻量任务可在既有问题/变更记录中完成。记录工程判断摘要，不要求输出内部推理过程。

## 恢复检查点

- 已完成单元、适用版本/配置、证据路径/claim ID。
- 尚未完成、失败边界、被否假设与阻塞。
- 当前设备/资源所有者、真实状态的来源/时间；无法重新检查即 unknown。
- 未决授权、反馈、偏好决策/期限；不重启或伪造计时。
- 唯一下一动作及前置；需重验的证据。

恢复先读取文件和新反馈，再核对源码/配置/产物/现场变化。命令已超时或进程仍运行时先查状态，避免重复烧录、迁移或启动占用设备的第二个进程。状态标 verified 不能代替其证据。

## 分工

需求、架构、实现、测试、质量、安全、运维和集成是职责，可由同一工程师分阶段承担。仅在授权且有价值时委派。并行写入按文件/模块分工；串口、调试器、执行器和真实记录由单一拥有者管理。审查结论引用外部产物，不通过相互重复断言形成“独立验证”。
