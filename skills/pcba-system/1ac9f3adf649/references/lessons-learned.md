# PCBA 开发事故与经验库（Lessons Learned）

> 每一条都是真金白银的翻车记录。对应清单里的否决项/检查项。
> 新案子开工前必读；每破一次新坑，追加一条并标注日期。

## A. 原理图类

### A1. 引脚映射取错封装列（2026-07，v3.1，最严重事故）
- **现象**：37 元件 127 引脚 100% 错位；U2(CH32V003) 引脚号取自数据手册 SOP16 列而非实际 QFN20 列——若流片，MCU 复位脚接地，永久报废。
- **根因**：ERC 只查内部一致性，不查是否匹配设计意图；"ERC 通过"被误当"设计正确"。
- **防护**：C2 清单封装列交叉核对（一票否决）；引脚名↔引脚号↔功能三方对齐留证据页码。

### A2. 网络标签按声明顺序摆放而非真实引脚
- **现象**：同 A1 并发；标签连线图在电气上"自洽"但完全不是设计意图。
- **防护**：原理图冻结前做 intent.connections 逐条对账（C2-08）。

## B. PCB 布局/布线类

### B1. 同一网络多引脚未物理连通（2026-09-21，D23）
- **现象**：U3 两个 9V 输入引脚只连了一个，另一个悬空——上电必挂。DRC unconnected 段抓出。
- **根因**：布线时只把网络"接进来"，没核对同网络的所有引脚对。
- **防护**：C4-01 未连接=0（一票否决）+ C4-03 同网多引脚抽查。

### B2. 板边过孔间距违规（2026-09-21，D23）
- **现象**：GND 过孔距板边 0.18mm（工艺要求 ≥0.3mm），崩边露铜风险。
- **防护**：C3-07 板边约束 ≥0.3mm；DRC copper_edge_clearance 段必须为 0。

### B3. 插装孔落入 SMD courtyard（2026-09-21，D23）
- **现象**：J1 插装孔与 C14 间距 0.45mm（组装要求 ≥0.5mm），courtyard 冲突。
- **防护**：C3-06 元件间距 ≥0.5mm 焊盘对焊盘。

### B4. 自动布线工具自身制造短路（2026-07，Freerouting）
- **现象**：U3 引脚区 0.65mm 间距处 9V/NRSS 缠绕短路。
- **教训**："用了正规工具"≠输出正确。任何工具输出必须过 DRC 复核。
- **防护**：C4-10；AI/自动工具的产出与手工产出适用同一门禁。

### B5. AI 新增走线引入新违规（2026-09-21，修复 B1 时）
- **现象**：第一版 9V 并接走线方案与 NRSS 走线交叉，间距仅 0.093mm——被 DRC 当场拦截后改道。
- **教训**：修复一个错误时可能引入新错误；修完必须全量 DRC，不得只查修复点。

## C. 制造/发布类

### C1. 下单参数文档与 Gerber 实际不符（2026-09-21，D23）
- **现象**：ORDER_README 写"2 层"，Gerber 实为 4 层——按 README 下单会流片失败。
- **防护**：C5-04 层数/板厚/尺寸一致（一票否决），已机器化（text_contains + zip_contains 检查）。

### C2. 状态看板滞后于真实状态（2026-07-26）
- **现象**：07-23 看板写"可打样"，07-26 检查报告实为 REJECTED，看板未同步——用户感知"板子一直有问题"。
- **防护**：每次 gate run 后同步更新状态看板；看板时间戳必须与最后一次 DRC 报告对齐。

### C3. 缺陷 Gerber 留在工作区（2026-09-21，D23）
- **现象**：含 P0 缺陷的旧 Gerber zip 与新版并存，有误传风险。
- **防护**：C5-06 旧版隔离 _superseded_<日期>/ 并标注禁止上传。

### C4. BOM 缺料号导致组装订单被拒
- **现象**：18/37 元件无 LCSC 料号，JLCPCB 自动核对必然失败。
- **防护**：C6-01 料号 100% 覆盖（一票否决），机器化（file_empty 检查缺料清单）。

### C5. CPL 极性方向不做旋转换算
- **决策**：脚本不做 JLC 旋转变换（无已验证数据源，瞎猜比不猜更糟）；人工在 JLC 网站 CPL 预览核对（C6-04，一票否决）。

## D. 流程/管理类

### D1. EDA 工具链中途迁移代价巨大
- **现象**：v3.1 在 EasyEDA Pro，D9 迁 KiCad，两轮全量返工。
- **教训**：工具链在 P0/P1 就定死并写入 intent；迁移 = 全级联失效重跑。

### D2. 环境变量坑（2026-09-21）
- **现象**：Git Bash 下 PROGRAMFILES 环境变量缺失导致 kicad_env.py 找不到 KiCad。
- **教训**：脚本环境检测要打印诊断；Windows 下优先用绝对路径探测。

### D3. 下载完整性（2026-09-21）
- **现象**：GitHub 直连被重置。
- **做法**：gh-proxy.com 镜像回退 + checksums.txt SHA-256 逐一校验，不跳过校验。

## E. 通用方法论（跨案适用）

1. **意图→指标→验证→证据 四件套**：没有证据路径的指标等于没有指标。
2. **一票否决项只增不减**：每个新事故必须变成某清单的一条否决项，否则下次还会翻。
3. **实验留痕**：每次自动布线/修复尝试记录输入、结果、失败模式；禁止在同一坑里重复三次。
4. **小步提交**：布局/布线的每次脚本化修改前备份（.bak-<日期>），修完全量 DRC 再覆盖。
5. **双人原则**：AI 执行 + 人审否决项；支付类操作只由人完成。
