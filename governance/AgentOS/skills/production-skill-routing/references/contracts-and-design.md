# Existing contract and design protocols

For req-spec-freeze, req-acceptance and req-trace, read installed AgentOS
UPFRONT-CONFIRMATION, TASK-PROTOCOL and QUALITY-GATE. Reuse existing project
goals, FRAMEWORK/interfaces, tasks, acceptance/claims and state paths. Record
baseline version/hash; link each requirement to design, Unit and verification.
Never silently change locked requirements or fabricate acceptance thresholds.
Use existing authorization; clarify only unresolved framework decisions.

For ui-design-system and ui-a11y, read DESIGN-CONSISTENCY.md in AgentOS. Resolve
the project's existing design authority first (DESIGN.md, theme or tokens).
Do not create another independently editable design source. Inventory actual
screens, flows, controls and loading/empty/error/disabled/focus states. Use
project typography, color, spacing and component tokens consistently. Record
target sizes/input methods, accessibility expectations and embedded RAM/frame
budgets before choosing. Inspect actual screenshots, overflow, keyboard/focus
and input behavior for visual claims. Reference sites supply ideas; counts,
licenses and conformance claims need evidence. No content is auto-fetched.

Outputs: baseline/traceability or design review in existing project files,
linked to actual evidence and independent review. Device/user acceptance
remains separate from static rules or simulation. The optional external
engineering-contract-and-confirmation Skill is not required by this provider;
a missing installation must never be reported as present.
